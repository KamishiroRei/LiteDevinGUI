## 改了什么

**`server.mjs`**（修改，相对基线 +151/-7 行）：

### POST /api/attach（扩展）
- 新增二进制请求体路径：`Content-Type: image/png|jpeg|gif|webp|bmp|avif|svg+xml` → 原始字节直接落盘 `attachments/img-<ts>-<rand>.<ext>` 返回 `{path}`，跳过 FileReader→base64→JSON。
- 兼容旧 `{dataUrl}` JSON 表单（另补 `image/avif`→`.avif` 扩展名映射）。
- 大小上限 `IMAGE_BYTES_CAP = 25MB`（二进制与 dataUrl 共用）；栅格类型做魔数嗅探与声明类型比对，**类型不符 415 / 超限 413 / 不支持的 image/* 415 / 空体 400**；body 先完整缓冲再写盘，失败不留半成品文件（发现读超限即丢弃已读分块，不先建文件）。

### GET /api/image-preview?path=<urlencoded绝对路径>（新）
- 本机任意绝对路径、存在且为常规文件、≤25MB、魔数嗅探为受支持栅格 → 200 原字节 + 嗅探出的正确 `Content-Type`。
- 响应加 `X-Content-TypeOptions: nosniff`、`Content-Security-Policy: default-src 'none'`、`Cache-Control: private, max-age=60`；SVG 与任何非栅格内容一律 415（同源可执行文档风险），相对路径 400、不存在/目录 404、超限 413。图片不经网络传输，只读本地盘。

### GET /api/session-images?sessionId=<id>（新）
- 从本进程已装载会话的历史缓冲抽取正文文本中的本机栅格图片路径；只扫 `user_message_chunk`/`agent_message_chunk` 的 text（不扫 tool_call 等工具日志），按首次出现顺序去重（NTFS 大小写归一）。
- `RASTER_PATH_RE`：盘符绝对路径，目录段允许空格与中文（NTFS 合法字符），扩展名后遇 `.` 或 `\w` 不终止——`a.png这张`、`a.png.txt`、`a.pngx`、`{{path}}`、`![x](path)`、引号包裹均按预期处理。
- 每个候选过滤：`existsSync`+常规文件+头 12 字节魔数嗅探为栅格（`.png` 文本假图也剔除）；仅 base64 无本地路径的图片自然跳过。
- 会话未装载 → 404 `session not loaded in this process`（与 `/api/bridge-text` 语义一致）。
- 返回 `{images:[{path, name}]}`，path 为 resolve 后绝对路径可直接喂给 image-preview。

### 配套
- 路由分发器支持 `{__raw: Buffer, contentType}` 裸字节响应哨兵（预览用）。
- fs 导入补 `openSync/readSync/closeSync`。
