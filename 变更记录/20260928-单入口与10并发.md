# 2026-09-28 Devin Lite 单入口与 10 条并发

## 问题与边界

旧桥梁允许显式 `DEVIN_BRIDGE_TRANSPORT=cli`，每个任务分别运行 `devin --print` 及其 ACP 子进程。实测两个旧任务各有独立 CLI/ACP，并锁住了 Lite 侧同名会话。按准确 actor 取消后，旧进程退出、会话锁释放；没有按进程名批量结束用户任务。`devin acp --help` 只提供 stdio，现有独立 CLI 的私有输入流无法由 Lite 接管；统一入口适用于后续经桥梁、GUI 和 Lite API 发布的回合。

## 已落地

- 禁止桥梁的独立 CLI 模型路径；`start`、续跑、action、后台 runner 只能进入运行中的 Lite 宿主。创建前确认 Lite/ACP 可响应，离线不创建 actor。
- Devin 并发上限固定 10。桥梁 `capacity` 输出当前占用、上限和余量；`start` 自动附快照，满额退出码 2 且不创建 actor/turn。Codex 可改选原生 Sol/Luna 子代理；Devin 发起时由当前会话自行执行。
- 内部 `run_subagent` 增加启动前 `reserve`，与桥梁共用机器级锁和计数；完成或启动失败后 `done` 释放。旧的启动后 `register` 只留作存量登记。
- Lite 「新会话」按钮显示当前 `运行中/10`，状态不可读显示 `?/10`；悬浮提示余量。空会话仍可创建，满额发送的 prompt 按已有延期队列处理。
- 同步仓库 AGENTS、CODEX/Devin 协作技能、架构和 README。

## 技术验证

- 本地容量脚本实测输出 `active=2, limit=10, available=8`，两个占位均来自同一 Lite ACP 的 busy session；没有第二个桥梁 `devin --print` 进程。
- 9 项桥梁单元检查通过：单宿主回合、取消边界、禁用独立 CLI、满额不建 actor、Lite 离线不建 actor、固定 10、子代理预留和释放等。
- Python 编译检查、`node --check`、两份 SKILL 结构验证通过。
