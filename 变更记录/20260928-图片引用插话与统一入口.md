# 2026-09-28 图片引用、插话与 Codex 统一入口

## 实现

- 图片文件粘贴优先复用资源管理器中的原始磁盘路径；只有剪贴板位图才在本机保存一次。位图走原始二进制上传，旧服务不支持时降级到 JSON 兼容路径。输入区用 `@图片N` 表示引用，悬浮可看预览；发送时展开为磁盘路径文本，允许与说明文字混排。当前会话输入 `@` 可按缩略图重用已有图片。未发出的引用删除后立即释放编号，下一张复用空出的 `图片1`。
- 同会话已有回合运行时，新消息直接调用 `session/prompt`；并发拒绝按服务端期限入延期队列。busy 采用引用计数，回显按各消息归属；前端用 `clientMessageId` 将失败与撤回按钮关联到具体用户消息。
- 新增桥梁回合 REST：`/api/bridge/turn/start|status|cancel`。Codex 桥梁默认经 Lite 的单个常驻 `devin acp` 创建/续跑会话；任务文件正文是 prompt，项目根目录 `--cwd` 是工作区。Lite 不可达时明确失败，不自动另起 Devin。跨任务容量锁内 start 完成后 busy 可见；归档中仍运行的会话计入容量。旧式独立 CLI 仅在显式 `DEVIN_BRIDGE_TRANSPORT=cli` 时使用。
- CODEX 已安装的 `devin-session-collaboration`、`codex-thread-communication` 手册与桥梁脚本已同步；仓库 `codex-skill/` 保存可追踪副本。模型证据区分“ACP 已选配置/接受设置请求”与“真实生成步骤”，不会合成 CLI 导出的模型字段。

## 技术验证

- `node --check server.mjs`、`node --check public/app.js`、`git diff --check` 通过。
- 后端 fake ACP：图片 21/21、插话 12/12、统一桥梁 v2 34/34。覆盖图片字节与预览、同会话插话、并发延期、会话创建/续轮、模型设置、权限、取消冲突及 host turn 状态。
- 桥梁隔离 Python 契约检查 3/3，通过容量归档计数、任务文件正文与 `cwd` 区分、start/status/取消协议。两个已安装 Codex SKILL 经 `quick_validate.py` 的 UTF-8 模式通过。
- 旧 8317 服务上的 Chrome 实测：复制位图时旧服务报 `invalid JSON body` 后兼容降级保存成功；删掉未发送的图片引用后再次粘贴复用 `图片1`；粘贴已有磁盘图片路径后 `@` 菜单出现该图片。此项证明旧服务兼容交互，不代替新服务的运行验收。

## 验收边界

- 8317 现役进程仍是修改前装载的代码，用户将自行重启；新服务端的图片缩略图历史、插话与统一桥梁需重启后由真实使用验收。
- 自动审批拦下了隔离环境中桥梁 `start` 的端到端验证命令，因此没有产生真实桥梁回合。本轮不以 fake ACP 或静态检查代替真实 Devin 使用验收。
- ACP `session/prompt` 立即接受插话不等于证明模型会在生成中立刻应用。ACP 模型设置只证明选中配置；真实单进程多会话并发上限与工作区信任行为还需运行观察。
- Lite 的 host turn 状态在内存中；重启后旧 ID 失效时桥梁要求先检查会话和产物，不自动重发。取消是会话级 ACP 操作；同会话另有在途插话时桥梁取消返回 409，避免误伤。
