## 改了什么

**`server.mjs`**（修改，相对基线 +224/-33 行）：

### 服务端归档（新功能）
- 新持久化文件 `archived-sessions.json`（`{version:1, sessions:{sessionId:{archivedAt, cwd?, title?}}}`），进程启动加载，损坏文件改名 `.corrupt-<ts>` 旁置并以空表启动（队列文件 `deferred-prompts.json` 同样加了容错旁置，此前损坏会静默丢队列）。
- 新端点：`POST /api/sessions/archive` `{sessionId, cwd?, title?}`→`{ok, archived:true}`；`POST /api/sessions/unarchive` `{sessionId}`→`{ok, archived:false, wasArchived}`；`GET /api/archived`→`{archived:[{sessionId, archivedAt(ISO), cwd?, title?}]}`（按 archivedAt 倒序，不依赖 agent、不依赖分页）。
- `GET /api/sessions` 每项新增 `_archived`/`_queued`（另保留 `_busy`）；默认过滤已归档，`?includeArchived=1` 原样返回并打标。**分页注意**：过滤发生在 agent 分页之后，某页可能变短甚至为空但 `nextCursor` 仍有效，前端需按游标继续翻页。
- `POST /api/sessions/delete` 同步清理归档元数据并发 SSE。归档/恢复广播 SSE `{kind:'session-archived', sessionId, archived}`。
- 归档是纯服务端元数据隐藏，不发任何 ACP archive 命令（无证据该命令存在）。

### 延期队列修复
- **`parseRetryAfterMs` 重大缺口修复**：原文本解析只认 `ms|s|秒|毫秒`，"wait 2 minutes"、"N分钟后重试"、"in 1.5 hours" 全部解析失败退回 60s 轮询——明示期限被当无期限处理，可能提前重发。现支持 minute/hour/分/分钟/小时（含小数），门槛词补 `稍等|等待|分钟`，结构化字段向 `error.data._meta`/`error.data.details` 下探一层，解析值上限 24h。
- **1 秒忙轮询修复**：到期但被容量/探针门拦下的条目 `retryAt` 恒为过去时，旧 `schedulePump` 把唤醒间隔钳到 1s，每 1s 拉起一次 `swe_capacity.py` 子进程。现按条目记 `lastCheckAt`，唤醒时机 = `未查过→retryAt；retryAt 在未来→retryAt；已到期被拦→lastCheckAt+RETRY_POLL_MS`，且无可派发条目时不跑容量探针。
- **重启恢复失效修复（根因）**：`ensureLoaded` 不调 `ensure()`，恢复队列的泵在任何 REST 触达前派发时，`request()` 对不存在的子进程静默写丢，条目永久卡死。现 `ensureLoaded` 先 `await this.ensure()`；ensure/spawn 失败标 `agentDown` 并按可重试错误重新入队（不丢用户消息）。
- **同会话顺序修复**：重发的条目原先 splice 出队、失败再 push 队尾，会被同会话后排队消息插队。现条目派发期间留队（`state:'sending'`），拒绝后原位回 `queued`；泵每 tick 维护 blocked 集，同会话前排不可派发则后排跳过；`POST /api/prompt` 遇会话已有排队项或有在途回合（`acp.busy`）也入队，不再并发直发。
- **commit 语义修正**：`commitDeferred` 加 `committed` 幂等守卫；`dispatchPrompt` 派发前统一 commit，失败后重排不再双写/漏写历史缓冲。
- **完成回踢**：`dispatchPrompt` 三种终局（成功/重排/普通错误）都 `void pumpDeferred()`，在途回合结束立即放行本会话后排，不用等下个轮询。
- `queueView` 增 `state`（queued/sending）与 `preview`（前 120 字符）；`POST /api/queue/drop` 只撤 `queued` 态（sending 已交 agent，撤不动，语义如实）；`/api/cancel`、`/api/sessions/delete` 仍按会话清全部排队项。

## API 契约（给前端接入）

- `GET /api/sessions?cursor&cwd&includeArchived` → `{sessions:[{…,_busy,_queued,_archived}], nextCursor?}`，默认不含已归档。
- `GET /api/archived` → `{archived:[{sessionId, archivedAt, cwd?, title?}]}`。
- `POST /api/sessions/archive` `{sessionId, cwd?, title?}` / `POST /api/sessions/unarchive` `{sessionId}`。
- `GET /api/queue` → `{pending:[{queueId, sessionId, attempts, state:'queued'|'sending', preview, queuedAt, lastError, retryAt?}], capacity, pollMs, limit}`。
- `POST /api/queue/drop` `{queueId} | {sessionId}` → `{removed, pending}`（只撤 queued）。
- SSE 新增 `session-archived`；沿用 `prompt-deferred/prompt-dispatch/prompt-done/queue/busy`。
