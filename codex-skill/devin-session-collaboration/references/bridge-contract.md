# 会话桥梁设计与验收契约

本页是 Codex 与 Devin 共用的通讯契约。程序入口为 `scripts/devin_bridge.py`，现役命令、架构与验证边界见 [桥梁 CLI](bridge-cli.md)。默认执行入口是 Devin Lite 的单个常驻 ACP：桥梁经本机 HTTP 发起和监视回合，SQLite 继续承担消息、结果与验收状态。SWE→SWE 的 action 在目标当前轮后续跑；SWE→Codex 的显式直达消息、最终报告和阻塞走原 Codex 宿主的 `send_message_to_thread` pipe。邮箱可在运行中主动读取；普通 `send` 的保存不等于模型已应用。

## 目标与边界

让 Codex、Devin 组织者、执行者和同级会话使用同一套操作发布任务、联系彼此、接收回复、继续原会话、收取成果和记录接受/返工。Codex 将 SWE-2 High 作为 subagent 使用，自身照常推进整体任务；角色随任务调整，调用方不因“子会话”身份失去派单或同级交流能力。通过 Lite HTTP → 同一 `devin acp` 的 `session/new|load` 与 `session/prompt` 驱动全部协作模型回合；旧式 `devin --print` / `--resume` 运行路径已禁用。

只需要一套任务内持久状态，不安装系统服务、不修改全局登录/模型配置。外部服务凭据只由 Lite 持有的 Devin ACP 使用，不进桥梁文件。桥梁不替代文件/项目授权，也不冒充操作系统沙箱。

## 状态所有权与架构

| 模块 | 职责、数据与流向 | 定位 |
|---|---|---|
| 统一 CLI | 调用方提交任务/消息，读取状态与结果 | scripts/devin_bridge.py；参数见 bridge-cli.md |
| 任务注册与邮箱 | 桥梁 ID、逻辑名称、真实 session ID、父/关联关系、原始任务、消息及投递状态 | 每任务 `bridge.sqlite3` 的 actors/messages/turns；`turns/<ID>/` 的导出与日志 |
| 调度与运行 | 队列 → 桥梁 runner → Lite HTTP → 同一 ACP 的会话回合 → 状态/日志；同一 actor 同时仅一个 runner | `spawn_runner`, `runner_loop`, `run_lite_turn` |
| 验收记录 | 产物已报告 → 验收者实际复核 → 接受或带理由返工 | 验收人/时间/证据位置与对应结果版本 |
| 主控事件唤醒 | 显式直达消息/最终报告/真实阻塞 → 持久 wake event → Codex app-tools 宿主发信；实际接收单独确认 | wake_events；`send`, `dispatch_wake`, `host_send`, `wake_ack`；普通 note/中间报告不触发 |

桥梁 ID、进程 ID 和 Devin session ID 不混用。消息记录至少含稳定 ID、发送者、接收者、关联任务、正文与时间；区分“已保存/送达”与“接收方已读取或模型轮次已消费”。消息和结论落盘；重启能恢复未投递内容，不把发送成功当成接收成功。

## 操作语义

- 发布：携带稳定项目/独立 checkout 根目录作为会话 cwd，任务书另写任务区绝对路径、目标、效果、必要材料和写入归属；返回稳定任务 ID，随后可异步获取真实 session ID、运行状态和结果。给接收者明确桥梁入口、自己的 ID、组织者 ID 和操作示例。任务子目录不是默认会话工作区，`--state` 也不决定工作区归属。
- 发现：列出当前协作任务内的会话和角色/状态，以便执行者选择同级或组织者；读取状态不触发模型。
- 消息：任意已注册参与者之间可发消息。普通 `send` 立即落邮箱，不建立后续轮次；接收方当前轮若正 `wait` 该发送者，约一个查询间隔内直接获得该工具返回，随后 `inbox --read` 标记已读。若接收方正在其他工作，须主动读取邮箱；桥梁不会把普通邮箱消息自动注入正在生成的模型。需执行的 `--action` 排到下一轮。Lite GUI 的插话直接作为同一 session 的另一条 prompt 发出，其可观察投递与模型应用仍分层记录。保留消息与已读/已交模型/已执行状态，不能静默丢信或把邮箱读取叫作自动 steer。
- 续跑：空闲会话收到需执行的任务时按确定 session ID 继续上下文；占用时排队，不能并发打开同一会话或换新会话冒充恢复。消息投递和需要模型续跑的请求可以区分，避免普通确认触发无限对话循环。
- 回报：执行者自主做到结束后提交产物、证据和未决项，接收者能独立读到结果。父会话与同级均可接收；Codex 可直接读取而不启动模型。
- 接受/返工：将结果版本、验收者、客观证据和结论记录在任务中。普通消息不需要审批；接受动作不凭一句“成功”自动完成。返工携带反证回到原会话。
- 取消/关闭：默认只请求取消桥梁记录的 host turn；Lite 会在同 session 存在其他在途 prompt 时拒绝会话级取消，避免伤及 GUI 插话。保存取消/失败和现有产物；不用全局进程名终止，也不擅自删除正式会话。历史独立 CLI 任务只能由原 runner 按准确 actor 结束；新桥梁不创建此类进程。

## 原聊天事件边界

Codex 派单后轻量确认任务正常启动、无明显运行故障即可放手；SWE 异步自主执行。Codex 有独立工作照常做，无事直接结束当前轮进入 idle，不持续监视、轮询或阻塞等待完成。SWE 自主执行和内部核验，有行动价值的协作消息可显式 `send --direct`；需主控整合的受委派任务完成用 `report --final`，真实阻塞用 `block`。未配置现有 Codex thread UUID 时，普通消息和报告仅保存到持久邮箱，三种直达命令则明确报错。已配置时，直达命令同事务保存事件，再经当前环境的 `CODEX_APP_TOOLS_PIPE_PATH` 调宿主 `codex_app/send_message_to_thread`，目标为事件中原线程 UUID。发信正文含事件索引和最多 2000 字符的实际消息/报告/阻塞内容；全文留在任务邮箱或报告。该入口与 Codex Agent 会话间发信同源；桥梁不再使用 CLI queue，也不在宿主失败后退回 queue。pipe 缺失/明确拒绝保留 `pending`，请求写出后无确定答复保留 `attempting`，宿主接受记 `submitted`，原聊天收到后才记 `received`。具体命令和恢复见 bridge-cli.md。

API 采用 CLI + JSON/文件参数；长任务书使用文件，中文与空格路径必须可靠。桥梁读取任务正文作为 prompt，`--cwd` 只作为会话工作目录；不把正文路径变成 Lite 工作区。禁止把模型文本拼接为 shell 代码；HTTP 用 JSON，不把输入拼成 shell 代码。后台进程隐藏窗口。

## 调度与自由度

默认执行者不需要中途向 GPT-6 反复报批，不强加固定阶段、拓扑或短任务长度。全局并发固定上限 10，遵循[准入正文](../SKILL.md#swe-并发准入与满额等待)：创建命令先报告占用并在满额时拒绝新 actor；已提交回合按实际运行去重 CLI/ACP、跨任务互斥启动，满额持久等待且每 5 分钟复查。`run_subagent` 前先预留名额，满额由 Devin 原会话自己执行。等待消息仍可到达；父任务不得占满所有名额后只等尚未运行的子任务。

工作范围、文件写入归属和共享运行资源仍需明确。同一工作目录可有不重叠的并行写入；重叠写入选择隔离或协调。非阻塞发布和读取接口不能把 Codex 的工具调用长期锁住。

## 必须实跑的验收

1. Codex 发布给两个独立 Devin SWE-2 High 会话，两者有实际重叠运行区间、不同 session ID 和可核对文件成果；真实会话模型为 swe-2-high。
2. 至少一个 Devin 会话自行使用桥梁创建另一个执行会话；内部发布、收信/读结果与回复均有实际工具调用及持久证据。
3. Devin 同级互相通信，消息在目标运行期间能保存并最终被读取/消费；双方能得到有用回复。回报能到达 Codex 的可读入口。
4. 指定会话续跑保留上下文；不只验证“又启动了一个进程”。CLI 明确恢复失败时不得回退新会话。
5. 结果报告与接受分离：Codex/组织者读产物并实际检查后记录接受；至少一条返工或纠正请求能到原会话并产出新结果。
6. 对持久消息并发写入、目标不存在/被占、进程失败/取消、重启恢复、模型不符和中文/空格路径做与实现风险相称的验证；确定性边界可用受控假进程验证，模型通讯主链必须用真实 Devin。
7. 多模态职责静态检查由 GPT-6 负责；本次通讯测试不冒充 UE/动画/特效实战验收。

## 完成与恢复

实现者交付代码、实际使用方法、架构定位、测试命令/结果、真实会话 IDs、消息 IDs、成果和验证报告。纯测试会话可在导出保存后回收；测试产生的文件留在任务区。现役技能的版本与已验证能力一致；不支持的功能说明真实条件。

数据损坏、身份无法验证或认证失效时保留状态并清楚报错；恢复动作按真实 session 和任务状态继续。代码升级不静默抹除已有队列与结果。
