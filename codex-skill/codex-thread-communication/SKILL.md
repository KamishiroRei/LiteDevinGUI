# Codex → Devin 协作

用于 Codex 处理用户已授权任务时的自主分工，无需用户另行提出使用 subagent 或执行会话。**有 Devin 名额时把 SWE-2 High 当作 subagent 使用；并发已满时按任务难度选择 GPT-6 Sol Max 或 GPT-6 Luna Max，其他工作按正常方式推进。**Codex 继续理解目标、判断方案、执行工作、整合结果、完成必要验证并向用户交付；在规划分工时主动评估协作收益。SWE 在受委派范围内自主完成探查、设计、实现、验证、排错和内部协作。省 token 通过有效委派、适当并行和减少重复检查实现，Codex 仍对整体任务的完成负责。

## 自主委派判断

每项执行任务在规划时评估是否有适合 SWE 独立交付的职责，以及并行、专长或减少主控 token 消耗的实际收益；有收益就主动派单，不等待用户说“用 subagent”。任务短小、不可合理拆分或委派成本超过收益时由 Codex 直接完成。委派继承原任务授权，不能扩大对象、权限或交付范围；需要范围外动作时按原任务授权边界处理。

## 模型与适用边界

全局 AGENTS 规定 subagent 路由：用户当次明确指定的模型与职责优先；否则优先通过 Devin CLI 的 SWE-2 High。日常委派由桥梁连接 Devin Lite 持有的单个 `devin acp`，并发已满时按任务难度选择 Codex 原生 GPT-6 Sol Max 或 GPT-6 Luna Max subagent。具体模型、容量与额度说明见 [执行者策略](references/executor-policy.md)。

涉及截图、视频、音频等多模态证据的实战验收，以及动画/特效制作，由 GPT-6 执行。相关问题分析、方案设计、代码和配置实现可交给 SWE-2 High；实现后把可复现步骤、产物位置与待判定表现交回 GPT-6。文字描述、静态检查和编译不能替代视觉或实战证据。

## 派单与自主协作

有 Devin 名额时，使用 [Devin 会话通讯](../devin-session-collaboration/SKILL.md) 的本地桥梁委派、收结果、续跑与取消。桥梁默认进入当前 Devin Lite 的单 ACP 宿主；Lite 不可达时明确失败，不能静默改用另一套独立 CLI。Devin session ID 与 Codex thread ID 不能混用。满额回退时使用 Codex 原生 subagent：Sol Max 为 `model: gpt-6-sol`、`reasoning_effort: max`；Luna Max 为 `model: gpt-6-luna`、`reasoning_effort: max`。这里的 subagent 指协作角色，载体由所选路由决定；用户明确要求 Codex 新聊天时才创建该聊天。

Codex 新建 Devin 会话前先确定该任务所属的稳定项目或独立 checkout 根目录，并将它传给桥梁 `start --cwd`；这也是会话在 Devin Lite 等客户端显示的工作区。任务书、桥梁 `--state`、隔离工作目录和产物可位于项目内的任务区，均以绝对路径传递并在任务书中限定读写范围，不能因为本次任务在某个子目录执行就把该子目录当作会话工作区。只有该目录本身确实是独立项目/checkout，或用户明确要求单列工作区，才用它作 `--cwd`。已有会话按其创建时的原始 cwd 续跑；不要为整理侧栏而换 cwd 冒充原会话。具体选择与示例见 [Devin 会话通讯](../devin-session-collaboration/SKILL.md#会话工作区与任务目录)。

委派提示尽量简短：说明目标、已知事实、可用材料和确属硬边界的范围与授权；需要验收时说明可观察结果。SWE-2 High 和 GPT-6 Sol Max 自主判断执行路径；交给 GPT-6 Luna Max 时，主会话写明执行方法和判定标准，不让 Luna 自行决定方案。

SWE-2 High 按旗舰执行者使用，可自主拆分、联系同任务执行者、建立有收益的子任务、相互咨询、转交任务、评审和排错。协作拓扑随任务调整，执行者可成为某个子目标的组织者；同级交流不必绕经 Codex，也不要求固定树形或逐级审批。这些动作继承原任务授权，无需为每个内部消息再次询问用户。委派不能扩大项目范围、发布权限或付费权限。模型不可用时明确返回条件，不静默更换模型。

默认不安排高频中途检查与纠正，也不要求逐阶段向 GPT-6 报批。执行者自行解决职责内问题；先在获授权的 Devin 同级或子任务间解决，真正需要主控决策、范围外授权或 GPT-6 专长时才升级。必要的过程记录用于恢复和执行者协作，主控无需逐条阅读。

独立任务并行；重叠文件按写入归属串行或隔离。编辑器实例、构建输出、运行端口等共享资源也有负责人。Codex 派发新的 subagent 前运行 `devin_bridge.py --state <任务状态目录> capacity`，读取 Devin 实际活跃数与固定上限 10：有名额才派发 SWE，已满按任务难度选择 Sol Max 或 Luna Max。桥梁 `start` 也自动返回容量快照，满额时退出码 2 且不创建 actor/turn。桥梁保留对已提交任务的后台等位能力；若预检后因并发竞争进入 `waiting_capacity`，先取消待执行的 SWE 并确认不会再启动，再改派所选执行者，避免双执行。主控可直接攻坚并保留其他执行者的独立进度。Devin 内部新建工作者按[并发准入正文](../devin-session-collaboration/SKILL.md#swe-并发准入与满额等待)执行；满额由原 Devin 会话自己完成，不回流给 Codex。

执行者间的派单、消息、回复与结论均经桥梁记录。SWE→SWE 的普通 `send` 立即入目标邮箱；目标本轮若正用 `wait` 等待该发送者，消息直接作为当前工具调用结果返回，随后 `inbox --read` 即可继续本轮。目标若正在其他工作中，只能在它主动读邮箱时获得消息，无法由发送方自动注入。`--action` 只在接收方当前 Lite/ACP 回合结束后续跑，不能用于当前轮直接引导。Lite GUI 的插话会直接提交同一 session 的新 prompt；已接受发送不等于模型立即应用。需要中途纠偏时按 [Devin 会话通讯](../devin-session-collaboration/SKILL.md) 的现役路径处理；身份、运行状态和结果以桥梁记录、Lite 会话与实际产物为准。

## 启动确认、异步托管与事件回送

派单时约定交付去向、完成证据和必要的回送条件。派单后用已有进程、状态和错误信息做轻量启动确认：任务已实际进入后台执行，没有明显运行故障，即可放手。启动确认只证明执行已开始，不等待完成报告，也不变成持续监视、逐阶段检查或反复查询进度。SWE 自主执行、自检和排错，复杂子任务可自行组织同级核验。

Codex 有其他可独立推进的工作就照常做；**无事可做时直接结束当前轮进入 idle**，不调用阻塞等待、循环查询或定时模型唤醒来占住主会话等 SWE。后台程序负责保存与投递事件；回送入口有未验证或不可用的边界时如实说明并保留成果，不以持续看护代替异步托管。subagent 表示分工角色，执行方式是异步自主执行、按需回送。

为有行动价值的事件回送主控：需要整合的受委派任务结果、需要主控决定的真实阻塞/范围变化，或到达 GPT-6 多模态职责。Devin 内部的普通进度、同级咨询和中间报告优先由执行者汇总为有结论的交付。Codex 根据整体任务继续工作；用户只需要成果且已满足完成标准时正常收口。

回送使用同一 Codex thread 的宿主发信入口，短消息包含任务/事件 ID、结论或正文摘要、成果索引和需要处理的事项；完整内容留在桥梁报告或邮箱。按事件 ID 去重，投递失败保留状态与错误；不重发整段会话、不反复问进度、不启动另一个 GPT-6 会话来代替原聊天。当前桥梁的 `send --direct`、`report --final` 和 `block` 已改为经 `CODEX_APP_TOOLS_PIPE_PATH` 调用宿主 `codex_app/send_message_to_thread`；不再调用 `codex queue`，也不在直达失败时静默排队。宿主接受、原聊天可见和模型实际处理分别判断。本次只核对协议与静态代码，真实回送尚未实战验证；具体命令和恢复见 [桥梁 CLI](../devin-session-collaboration/references/bridge-cli.md)。

投递方式与模型是否工作分开判断。Codex 自己的会话间发送使用宿主工具 `mcp__codex_app__send_message_to_thread`，Codex 内部子代理另有 `collaboration.send_message`。SWE 的 Devin CLI 不直接获得这些工具，但本桥梁现在用 Codex 宿主注入的本地 pipe，按 `codex-app-tools` 的帧协议固定调用 `send_message_to_thread`，目标只能是该任务绑定的原聊天 UUID。当前 Codex 环境已只读确认该 pipe 的工具目录含 `codex_app/send_message_to_thread`；消息投递尚未实测，不能把代码接通当成活跃轮已收到。运行时若 pipe 不可用或宿主拒绝，事件保留为 `pending`；发送后断连或超时保留为 `attempting`，确认原聊天状态后才允许重试。旧 `queued` 事件只作为历史状态保留。直接引导在安全边界生效，不等于撤销已经开始的工具。

“工具等待没有模型输出”“当前轮已结束进入 idle”“回调消息成功入队”“同一聊天实际被唤醒”是不同状态。首次部署须实证最后一项；邮箱落盘、CLI 退出 0 或活跃轮收到消息均不能代替 idle 唤醒。若当前宿主没有可用回送入口，明确报告这一限制并保留结果，不能声称自动唤醒已完成。

## 回收、验收与失败处理

执行者报告改动、证据和未决项。Codex 按正常工作方式整合结果、完成必要验证并对整体交付负责，利用执行者已提供的可靠证据避免重复劳动。具体验收可按分工由 Devin 同级或组织者执行；执行完成、自检、独立接受和用户接受分别记录，没有独立核验时如实标为自检完成。未通过则把具体反证发回原会话续做。回送事件到达后，Codex 按整体任务需要继续推进。多模态结果依上面的职责交 GPT-6；用户接受单独标注。

续跑使用明确的执行者 ID 与实际 Devin session ID，不靠最近会话。被占、认证失败、无上下文恢复失败、模型不符或进程退出均要保留可诊断状态；不把新会话冒充旧会话恢复。父执行者等待子任务时仍应能收信，调度不能因所有槽位被等待者占据而死锁。没有新事实时不催促。

本次结束前记录实际改动、证据、未决项和恢复路径。正式会话与结果保留；纯测试会话在证据保存后由测试负责人回收。旧手册的原始存档及恢复规则见执行者策略。
